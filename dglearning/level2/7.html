7. Populating ETSDB with System link data

  1. New topic: Server-side data flows are different than previous dataflows.
    1. No undo and instant saves with change, i.e. live data
      1. This can also mean lag when dragging connections and moving things.
      2. Move slowly and carefully when working with server-side dataflows.
  2. Click on dataflow button next to createHistories
  3. Drag out List Node block
    1. New block: takes everything from data link and puts it into a table
  4. Drag out “System” data link
  5. Connect System path to listNode path
  6. Delete System data link
    1. This workflow ensures proper path info by removing opportunity to type path wrong. It is also very fast.
    2. Result: hardcoded path to System data link
  7. Open children table
    1. Compare to Metrics panel
    2. Note different columns
  8. Close table
  9. Bring out a repeater block
    1. Will be used to repeat an operation. In this case, it is going to be used to publish the data from the listNode table into the ETSDB.
    2. A data symbol will be used to complete this operation.
  10. Bring out a concat block
    1. Convert to symbol
    2. Name: “generateHistories”
  11. Select repeater block
    1. Symbol: “generateHistories”
    2. Right-click on repeater block > Edit Symbol
      1. Note that there is a “0” index next to Edit Symbol
    3. Drag in mapToTable block
      1. New block: mapToTable
        1. Extremely useful block - references a specific row of a table.
      2. Open output table
        1. Note that it brings in the “0” row from the listNode block
    4. Click “Ok” to save and close
  12. Select listNode block
    1. Open children table
      1. Notice that there are commands present in the table. We are only interested in points.
      2. Close table
    2. Select “points” from mode dropdown.
    3. Open children table to see change then close table.
  13. Select repeater block
    1. Right-click on repeater
    2. Change edit symbol index to 4
    3. Click Edit Symbol
    4. Check output of map to table block
      1. Notice that it says Free Disk Space, which was index 4 in the listNode table of points.
        1. It shows as row 0 here because it is in a new table.
    5. Click OK to save and close symbol.
  14. Creating server data points with symbol/repeater
    1. Select repeater block
    2. Right-click on repeater
    3. Change edit symbol index to 0
    4. Click Edit Symbol
    5. Drag out architecture data point (load value)
    6. Open map to table output
    7. Select concat block
    8. Input 0: “data/systemDataHistories/”
    9. Expand side panel to check if there are any typos
    10. Drag “Architecture” cell from map to table output onto input 1 of concat
    11. Change architecture load value block to “metric”
      1. Because this is inside of a symbol, it will be repeated to publish data from each point inside of “system”.
  15. Creating new database and watchgroup
    1. Right click on ETSDB > Add Database
    2. Name: “systemHistories”
    3. Path: “db”
    4. Click Invoke
    5. Right click on systemHistories > Create Watchgroup
    6. Name: “system”
    7. Click Invoke
  16. Adding Watching Paths
    1. Right click on system, drag out Add Watch Path
    2. Connect output of concat block to Path of addWatchPath block
    3. Set autorun to enabled
  17. Data connections and null check
    1. Duplicate metric load value block
    2. Connect path from concat block
    3. Drag out length block
    4. Drag out if block
      1. Op: >
      2. Input1: “0”
      3. Then: “false”
      4. Else: “true”
    5. Connect output of metric1 to length
    6. Connect output of length block to input of if block
      1. Note: output of if block will check whether the metric currently has a value.
    7. Connect output of if block to enabled
  18. Setting server data points
    1. Right click on systemDataHistories, drag out set block
    2. Connect
    3. Connect
    4. Enable
  19. Note: points populated in metrics window.
    1. Arrow/bar icon shows that they have histories
      1. Timestamped and stored in our ETSDB
